# Telegram-уведомления о новых заявках

Когда клиент отправляет заявку на странице записи, вам в Telegram приходит личное сообщение:

```
📸 Новая заявка на фотосессию!

👤 Клиент: Анна Иванова
📱 Телефон: +7 900 123-45-67
📸 Вид съёмки: Love Story
📅 Желаемая дата: 20.11.2026
⏰ Время: 18:00
📍 Локация: Москва
📝 Комментарий:
Хотим фотосессию на закате.
```

Заявка также сохраняется на сервере и появляется в разделе **«Заявки»** приложения.

## Как это устроено (и почему безопасно)

```
Страница записи (GitHub Pages) ──▶ Cloudflare Worker ──▶ Telegram Bot API ──▶ вам в Telegram
Приложение фотографа ◀── список заявок (по секретному ключу) ◀── Cloudflare Worker
```

Токен бота знает **только Worker**. В файлах на GitHub его нет, и никто не увидит его, открыв код сайта.
Бесплатного тарифа Cloudflare хватает с огромным запасом (100 000 запросов в день).

Вам понадобятся три значения, которые вы создадите ниже. Выпишите их в заметки на телефоне:

| Что | Откуда берётся | Куда вставляется |
|---|---|---|
| **BOT_TOKEN** | @BotFather | Cloudflare → секрет `BOT_TOKEN` |
| **CHAT_ID** | getUpdates (шаг 2) | Cloudflare → секрет `CHAT_ID` |
| **ADMIN_TOKEN** | вы придумываете сами | Cloudflare → секрет `ADMIN_TOKEN` и приложение → Настройки |

---

## Шаг 1. Создайте бота в BotFather

1. В Telegram найдите **@BotFather** (с синей галочкой) и нажмите «Запустить».
2. Отправьте команду `/newbot`.
3. Введите **название** бота — любое, например `Polyanskaya Photo Заявки`.
4. Введите **username** бота — латиницей, обязательно оканчивается на `bot`, например `polyanskaya_photo_bot`.
5. BotFather пришлёт сообщение с **токеном** вида `123456789:AAExampleExampleExampleExample`. Это и есть **BOT_TOKEN**.

> ⚠️ Токен — как пароль от бота. Никому его не отправляйте и не вставляйте в файлы проекта и на GitHub.
> Если он случайно попал в чужие руки: в BotFather отправьте `/revoke`, выберите бота — получите новый токен.

## Шаг 2. Узнайте свой Chat ID

1. Откройте своего нового бота (ссылка в сообщении BotFather) и нажмите **«Запустить»** / отправьте `/start`.
   **Это обязательно:** пока вы не написали боту первой, он не может писать вам.
2. Отправьте боту любое сообщение, например `привет`.
3. В браузере на компьютере откройте адрес (подставьте свой токен вместо `ВАШ_ТОКЕН`):

   `https://api.telegram.org/botВАШ_ТОКЕН/getUpdates`

   Слово `bot` перед токеном остаётся: получится `.../bot123456789:AAExample.../getUpdates`.
4. На странице найдите кусок `"chat":{"id":123456789,` — число после `"id":` и есть **CHAT_ID**.
   Если страница пустая (`"result":[]`) — вы не написали боту (шаг 1–2), напишите и обновите страницу.

Запасной способ: напишите боту **@userinfobot** — он ответит вашим ID.

## Шаг 3. Придумайте ADMIN_TOKEN

Это ключ, по которому приложение получает список заявок. Придумайте длинную случайную строку из 30+ символов
(латиница и цифры), например, сгенерируйте в менеджере паролей. Сохраните в заметки.

## Шаг 4. Создайте Worker в Cloudflare

Названия кнопок в Cloudflare иногда немного меняются, но порядок действий тот же.

1. Зарегистрируйтесь на **dash.cloudflare.com** (бесплатно, нужна только почта).
2. В меню слева: **Workers & Pages** → **Create** → **Create Worker**.
3. Название: `polyanskaya-booking` → **Deploy**. (Получится адрес вида `https://polyanskaya-booking.ВАШ-АККАУНТ.workers.dev`.)
4. Нажмите **Edit code**. Удалите весь код в редакторе, откройте файл `backend/telegram-worker.js` из проекта, скопируйте всё содержимое и вставьте. Нажмите **Deploy**.

## Шаг 5. Подключите хранилище заявок (KV)

1. В меню слева: **Storage & Databases** → **KV** → **Create a namespace**. Название: `BOOKINGS`.
2. Вернитесь в **Workers & Pages** → ваш Worker → **Settings** → **Bindings** → **Add** → **KV namespace**.
3. **Variable name** — строго `BOOKINGS` (заглавными). Namespace — только что созданный. Сохраните.

## Шаг 6. Добавьте секреты и переменные

Worker → **Settings** → **Variables and Secrets** → **Add**.

Тип **Secret** (значение после сохранения не показывается):

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `CHAT_ID` | число из шага 2 |
| `ADMIN_TOKEN` | ваша длинная строка из шага 3 |

Тип **Text** (обычные переменные):

| Имя | Значение |
|---|---|
| `ALLOWED_ORIGIN` | адрес вашего сайта на GitHub Pages **без слэша на конце и без имени репозитория**, например `https://anna.github.io` |
| `APP_URL` | (необязательно) полный адрес приложения, например `https://anna.github.io/polyanskaya-photo/` — в Telegram появится кнопка «Открыть приложение» |

Нажмите **Deploy**.

> `ALLOWED_ORIGIN` — защита: Worker принимает заявки только со страницы вашего сайта.
> Если у вас несколько адресов, перечислите их через запятую.

## Шаг 7. Проверьте Worker

Откройте в браузере `https://polyanskaya-booking.ВАШ-АККАУНТ.workers.dev/health`. Должно быть:

```
{"ok":true,"telegram":true,"storage":true}
```

- `telegram:false` → не заданы `BOT_TOKEN`/`CHAT_ID` (шаг 6).
- `storage:false` → не привязан KV с именем `BOOKINGS` (шаг 5).

## Шаг 8. Подключите страницу записи

1. Откройте файл `config.js` и впишите адрес Worker (без `/` на конце):

   ```js
   BOOKING_ENDPOINT: "https://polyanskaya-booking.ВАШ-АККАУНТ.workers.dev",
   ```

   Здесь же можно поменять список видов съёмок для клиентов (`BOOKING_TYPES`) и указать свой Telegram (`CONTACT_TELEGRAM`).
2. Загрузите изменённый `config.js` в репозиторий на GitHub (как в README). Подождите минуту.
3. Закройте приложение на iPhone и откройте его дважды — вторая загрузка подхватит новый файл.

## Шаг 9. Подключите приложение

1. В приложении: **Настройки** → **Онлайн-запись** → вставьте **ADMIN_TOKEN** в поле «Ключ доступа» → **Сохранить ключ**.
2. Нажмите **«Проверить связь»** — должно появиться «Всё работает: сервер и ключ в порядке».

## Шаг 10. Тест от начала до конца

1. В Настройках нажмите **«Отправить»** у ссылки для клиентов (или откройте `…/booking/` в браузере).
2. Заполните форму и отправьте.
3. Клиент видит: «Спасибо! Ваша заявка отправлена фотографу…».
4. В Telegram приходит сообщение от бота.
5. В приложении, в разделе **«Заявки»**, появляется новая заявка (приложение проверяет их при открытии; можно нажать «Проверить новые заявки»).

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Страница записи пишет «Онлайн-запись сейчас недоступна» | В `config.js` пустой `BOOKING_ENDPOINT` или файл не обновился на GitHub |
| «Не удалось отправить заявку» / «Нет связи» | `ALLOWED_ORIGIN` должен совпадать с адресом сайта **точно** (`https://логин.github.io`, без `/` и без имени репозитория, с `https`) |
| Заявка отправляется, но в Telegram тишина | Вы не нажали «Запустить» у бота; неверный `CHAT_ID`; неверный `BOT_TOKEN` (проверьте через `/health` → `telegram:true`, а токен — ссылкой `https://api.telegram.org/botТОКЕН/getMe`) |
| Telegram приходит, а в приложении пусто | Не привязан KV (`storage:false`) или не введён ключ в Настройках; нажмите «Проверить связь» |
| «Ключ доступа не подходит» | В приложении и в Cloudflare `ADMIN_TOKEN` должны совпадать символ в символ |
| «Слишком много заявок» | Защита от спама: не больше 5 заявок в час с одного устройства |

Логи Worker: Cloudflare → ваш Worker → **Logs** (Observability).

## Безопасность — коротко

- Токен бота и Chat ID лежат только в секретах Cloudflare, в репозитории их нет.
- Список заявок отдаётся только по `ADMIN_TOKEN`; после 20 неверных попыток с одного IP за час доступ блокируется.
- Заявки принимаются только с адреса из `ALLOWED_ORIGIN`, данные проверяются и очищаются, в Telegram-сообщении экранируется HTML.
- В заявках лежат имена и телефоны клиентов — храните `ADMIN_TOKEN` так же бережно, как пароль. Заявки на сервере удаляются сами через 90 дней.

## Вместо Cloudflare: Supabase Edge Functions

Логика Worker (проверка данных → запись → вызов `sendMessage`) переносится в Edge Function почти без изменений.
Из приложения нужно поменять только адрес в `config.js` и формат ответа `GET /bookings` (`{ ok, bookings: [...] }`) — см. `js/sync.js`.
Готовая функция для Supabase в проект не включена: основной и проверенный вариант — Cloudflare Worker.
